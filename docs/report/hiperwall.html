Wallwright and Hiperwall

A head to head against the closest commercial equivalent.

Prepared for the Wallwright exhibit · 24 August 2026 · verified marks a claim a cited source states. unverified marks inference or something not checked. Platform details are quoted from each vendor's own documentation.

Why Hiperwall, and not Userful

An earlier report ranked Userful the best commercial fit. Userful's own documentation rules it out for this job: it is "a complete Linux-based operating system derived from Red Hat Enterprise Linux (RHEL) 9", running on a dedicated server and streaming content over RTSP to a decoder device behind each display. The exhibit runs on a Windows PC, so Userful would mean replacing the machine, its operating system and its GPU, and then streaming a web page to a screen already attached to a computer that could render it. verified

Hiperwall is the right comparison. It runs on Windows, on commodity PCs, and it renders web pages with a real browser rather than streaming video. It is the closest thing to Wallwright that can be bought.

What each one is

Hiperwall

Software on ordinary Windows machines. "All Hiperwall PCs require Windows 10 or 11 (32 or 64 bit) and Gigabit Ethernet", and it "runs on standard PCs connected by standard Ethernet". Each display is driven by a PC running HiperView, and one PC can drive several displays. verified

Crucially, its web support is not a screen capture. HiperSource Browser is described as a real web browser based on the Chromium engine, providing a direct connection between web content and the wall and bypassing the screen capture approach. Keyboard and mouse control of a source comes through a separate HiperKVM licence. verified

Wallwright

A single application on the show PC. Each panel is a real browser view composited onto the wall's output, and input reaches it the way it reaches a browser tab. verified

So the two agree on the hard architectural question. Both reject streaming, both put a real browser engine on the wall, and both run on Windows. The differences are everywhere else.

The licensing shape is the sharpest practical difference

Hiperwall licenses per display, and every browser tab consumes a HiperSource licence. The exhibit's whole idea is a montage of live pages, and the editor now lets someone add panels at the wall. Under that model, the natural act of adding a panel has a purchase order attached to it. Wallwright's panel count is free, which is not a small difference for an exhibit whose layout is meant to be changed.

Where Hiperwall wins

  • Non-web sources. Cameras, video, IP streams, remote desktops. Wallwright does web pages and nothing else. verified
  • Scale. Many displays, many nodes, one wall or several. Wallwright drives one output.
  • Redundancy. HiperFailSafe runs a second controller. verified
  • Maturity and support. A maintained product with an external API, outliving whoever wrote the exhibit. verified
  • It has done this before. Real installations, real control rooms. Wallwright has never run a show.

Where Wallwright wins for this exhibit

  • One machine, no licence, no per-panel cost. It runs on the PC that is already driving the wall.
  • Interaction without a KVM layer. Clicking and typing are native, not a licensed feature.
  • Arranging the montage on the live wall, against the real dashboards at the real resolution, rather than authoring layouts in a console. unverified that Hiperwall cannot do this
  • Several panels behind one login. Four dashboards from one SSO-protected application share a session instead of needing four sign-ins. No vendor documents an equivalent. unverified
  • Measured against this exact job. Session behaviour, memory, and the interaction model were tested for this exhibit, not inferred from a datasheet.

Cost, honestly

Hiperwall does not publish pricing, so the comparison cannot be made in numbers. unverified What can be said is the shape: a per display licence, plus a HiperSource licence per browser tab, plus HiperKVM for interaction, plus HiperFailSafe if redundancy is wanted. Against that, Wallwright costs the engineering already spent and nothing recurring.

The costs that do not appear on either invoice are the ones worth weighing. Buying brings support and someone else's testing. Building brings an exact fit and a dependency on whoever maintains it.

Recommendation

For this exhibit as scoped, Wallwright is the better fit, mainly because the licensing model taxes the thing the exhibit is built to do, and because a single wall of web pages does not need a controller and display nodes.

Hiperwall becomes the right answer if any of these turn out to be true:

  1. The exhibit needs camera, video or remote desktop sources.
  2. It grows to several walls, or many displays.
  3. Unattended reliability with failover becomes a hard requirement.
  4. Honeywell will not accept an unsigned in-house application, but will accept a commercial product. Worth asking early, because it decides everything else.
  5. Overlay compositing fails on Windows. This is the one unverified assumption underneath Wallwright. Hiperwall has clearly solved the equivalent problem, and if ours does not hold, buying gets much more attractive.

What is still unverified

  • Hiperwall pricing, in any form.
  • Whether one Windows PC can serve as both HiperController and HiperView node, which decides whether this is a one machine or two machine deployment.
  • Whether either product handles a real Honeywell SSO flow. Hiperwall's material mentions users logging in to restricted sites, which is the closest anyone comes, but it is not a commitment. verified as a claim, not as behaviour
  • Wallwright's overlay compositing on Windows. A check is running against a Windows machine; until it reports, this is the largest open risk in the project.
