Wallwright and Userful

A head to head, and a correction to an earlier recommendation.

Prepared for the Wallwright exhibit · 24 August 2026 · verified marks a claim a cited source states. unverified marks inference or something not checked. Userful's architecture is quoted from Userful's own documentation.

A correction

An earlier comparison ranked Userful the best commercial fit for this exhibit, largely on published pricing and documented tablet control. Reading Userful's own hardware documentation changes that. Userful is not software you install on the show PC. It is a Linux operating system, on its own certified server, streaming video to a decoder device behind each display. For a single wall driven by a single Windows PC, it is the wrong shape, and its rendering model is the one this project rejected at the design stage.

What each one actually is

Userful

A platform, not an application. From Userful's documentation:

"Userful on-premise is, at its core, a complete Linux-based operating system derived from Red Hat Enterprise Linux (RHEL) 9." verified

Content reaches displays indirectly. Sources are ingested at the server, in part through Blackmagic DeckLink capture cards for HDMI and SDI inputs, and then streamed to uClient endpoint devices over RTSP. A uClient runs on a smart display's own processor or on an Android adapter behind each screen. verified

The server needs a certified NVIDIA Quadro or RTX A-series GPU, from a list that runs RTX 4000 through A6000, because the GPU decodes and encodes the video. Deployments past twelve displays need 10 Gb network interfaces. verified

Wallwright

An application. It runs on the show PC, on Windows, and draws each panel as a real browser view composited directly onto the wall's output. Nothing is encoded, streamed or decoded. Input reaches a panel the way it reaches a browser tab, so clicking and typing need no remote-control layer. verified

Why the streaming matters here, specifically

SPEC.md considered capture based approaches at the outset and rejected them, because what lands on the wall is a video texture and native interaction is lost: making it interactive means mapping wall coordinates back into an offscreen browser and injecting synthetic input. Userful's architecture is a well engineered version of exactly that shape, with the interaction added back through its own remote control layer. That is a reasonable trade for a control room streaming cameras and desktops across a building. It is a strange trade for one wall showing four web pages, sitting on top of the PC that could simply render them.

Where Userful clearly wins

  • Anything that is not a web page. Cameras, HDMI, SDI, remote desktops, video conferencing. Wallwright does web pages and nothing else. verified
  • More than one wall, or more than one room. This is what the architecture is for, and it is why the architecture looks like that.
  • Redundancy. A second failover server. Wallwright has none, and on one PC cannot have one. verified
  • A support contract and a maintained product that outlives whoever wrote the exhibit.
  • Mature remote control, including operators driving mouse and keyboard from a desktop or smartphone. verified

Where Wallwright wins for this exhibit

  • Native rendering and native input. No encode, decode, stream or coordinate mapping between the operator's hand and the page.
  • It runs on the machine that is already there. No second server, no endpoint device, no operating system change, no GPU purchase.
  • Arranging the montage on the live wall. Drag panels around against the real dashboards, at the real resolution. Userful's layouts are authored in a console. unverified that Userful cannot do this
  • Several panels behind one login. Four dashboards from one SSO-protected application share a session rather than needing four sign-ins. No vendor documents an equivalent. unverified
  • No recurring cost and no vendor dependency.

Recommendation

For this exhibit as scoped, Wallwright is the better fit, and the reason is architectural rather than financial. Userful would mean replacing the show PC with a Linux server, buying a certified GPU and an endpoint device, and then streaming a web page to a display that is already attached to a computer capable of rendering it. The $500 licence is the smallest part of that.

Userful becomes the right answer if any of these turn out to be true:

  1. The exhibit needs camera, HDMI or desktop sources, not only web pages.
  2. It grows to several walls or rooms.
  3. Unattended reliability with failover becomes a hard requirement.
  4. Honeywell will not accept an unsigned in-house application on the show PC, but will accept a commercial platform. That is a real possibility and worth asking early.
  5. Overlay compositing fails on Windows. This is still the one unverified assumption underneath Wallwright, and the fallbacks are more awkward. If it fails and the fallbacks disappoint, the build versus buy question genuinely reopens.

What is still unverified

  • Whether Userful can drive displays directly from the server's own outputs rather than through streamed endpoints. Zero clients were deprecated in version 12.7, and the current documentation describes streaming. A direct-attached configuration may exist. unverified
  • Whether Userful handles a real Honeywell SSO flow. No vendor documents this.
  • How interaction feels through a stream. Latency was not measured and may be perfectly acceptable.
  • Wallwright's overlay compositing on Windows, which remains the largest open risk in the project.
